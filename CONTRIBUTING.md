# Contributing

Thank you for contributing.

## Before opening a change

1. Check existing issues and pull requests.
2. Open an issue for substantial feature proposals or architectural changes.
3. Keep changes focused and avoid unrelated refactoring.
4. Never include secrets, credentials, personal data or patient-identifiable information.

## Pull requests

Please describe:
- what changed;
- why it changed;
- how it was tested;
- any known limitations or follow-up work.

Run the repository's documented build and test commands before submitting a pull request.

## Issues

Use the available issue templates where applicable. Provide reproducible steps, expected behaviour and actual behaviour for bugs.

## Review standard

Changes should be understandable, reproducible, documented where necessary and consistent with the project's security and privacy requirements.
